# Статусы документации

Этот файл описывает, как мы помечаем состояние статей в документации CustomKnits.

## Где хранится статус

Статус хранится во front matter статьи:

```yaml
status: "wip"
```

В локальной сборке статус показывается цветной плашкой на странице и в `/dev-progress`.

В production-сборку не попадают статьи со статусами `todo`, `wip`, `needs-fix`, `requires-fix`, `needs-review`, `outdated` и `legacy`. Статус `draft` пока используется для обзорных страниц-каркасов разделов и остается в production, если сам раздел должен быть виден.

Если после изменения статуса локальная сборка показывает старые данные или странно обновляет список статей, перезапустите dev-сервер через `npm run dev:clean`.

## Основные статусы

### `todo`

Статью нужно написать или сильно переработать.

Когда использовать:

- есть только заглушка;
- структура статьи еще не согласована;
- в статье нет основной информации;
- статья создана как будущая ссылка из другой статьи.

Плашка: `TODO`.

### `wip`

Статья сейчас в работе.

Когда использовать:

- статья уже полезна;
- часть текста и скриншотов есть;
- мы еще ожидаем правки, проверку логики или дополнительные материалы;
- статья не готова считаться стабильной.

Плашка: `WIP`.

### `done`

Статья готова для текущей версии продукта.

Когда использовать:

- текст согласован;
- скриншоты актуальны;
- ссылки проверены;
- нет известных открытых вопросов;
- статья не требует срочного обновления.

Плашка: `DONE`.

### `needs-fix`

Статью нужно исправить.

Когда использовать:

- в редакторе изменилось поведение, которое описано в статье;
- скриншоты устарели;
- статья противоречит текущей логике продукта;
- пользователь или команда явно заметили проблему;
- основной репозиторий редактора позже определил, что статью нужно проверить.

Плашка: `FIX`.

## Совместимые старые значения

Эти значения поддерживаются, но для новых статей лучше использовать основные статусы выше.

```yaml
status: "draft"        # показывается как TODO
status: "current"      # показывается как DONE
status: "needs-review" # показывается как FIX
status: "outdated"     # показывается как FIX
```

## Что не делаем сейчас

Пока не заводим в docs-репозитории карту областей редактора и триггеров обновления.

Позже основной репозиторий редактора сам сможет определить, какие области продукта относятся к каким статьям, и при необходимости проставлять `needs-fix` или формировать список статей для проверки.
